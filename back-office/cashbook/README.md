# 資金表 → 現金出納帳

現金と預金が合算された「資金表」から、預金・銀行取引を除いて**現金だけ**を抜き出し、
現金出納帳を作るためのツールです。毎月繰り返す照合作業を短くすることが目的です。

```bash
npm run cashbook      # http://localhost:3100/back-office/cashbook/index.html
```

---

## この作業のいちばん大事な原則

**色分けは判断の目安にすぎません。**
青＝銀行振込、黒・赤＝現金という一次判定はしますが、それだけでは確定できません。
必ず銀行通帳の記載と取引内容で裏取りしてから確定します。

このツールはその原則をそのまま形にしています。

| 判定の根拠 | 扱い |
|---|---|
| 人が確認して確定した | **確定**（機械があとから覆さない） |
| 登録ルールに一致 | **確定**（過去に人が確認した判断の再利用） |
| 通帳に同じ動きがある | **確定**（裏取りが取れている） |
| 色だけ | **未確定**（必ず1件ずつ確認に回る） |

「まとめて確定」ボタンは、上の3つに当たる行だけを対象にします。
**色だけで判定した行が一括確定されることはありません。**

## 手順

### 1. 読み込み

**対象月の設定**
- 期首残高（手許現金）を入れます
- 逆算した推定値のうちは「推定値」にチェックを入れたままにしてください。出納帳に `※逆算した推定値` と表示され、未確認であることが残ります
- 現金純増減の目標値が分かっていれば入れます（検算に使います）

**資金表を読み込む**
- **必ず .xlsx のまま読み込んでください。** CSV に書き出すと文字色が失われ、一次判定ができなくなります
- 文字色・日付・金額を直接読み取ります。列（日付／摘要／入金／出金／残高／科目）は自動で判定し、違っていればその場で選び直せます
- 金額欄が空か 0 の行は集計に入れられないため、**行番号つきで一覧表示します**。ATM引き出しのように内訳を分ける必要がある行がここに出ます。黙って捨てることはしません

**銀行通帳を読み込む**
- ネットバンキングの入出金明細CSV。文字コード（Shift_JIS / UTF-8）は自動判定します

### 2. 仕分け

「要確認」だけを表示した状態で始まります。1件ずつ **現金／銀行／除外** を押して確定します。

確定すると「今後も同じ判定にしますか？」と聞かれます。**はい**と答えるとルールとして保存され、
翌月以降は自動で当たります。判断の根拠（なぜ除外するのか）もあわせて残せます。
これを続けるほど、翌月の「要確認」は減っていきます。

**分割**
ATM引き出しのように 1 件が複数の性格を持つ取引は「分割」で内訳に分けます。
内訳の合計が元の金額と一致しないと保存できないので、金額がずれることはありません。
分割したあとの親行は集計から外れ、二重計上されません。

### 3. 検算

```
現金純増減 ＝ 資金表残高の増減 − 銀行通帳上の動き
```

この計算値と「現金と確定した取引の合計」が一致すれば、仕分けに漏れがありません。
差異が出る典型的な原因は次の2つです。

- 通帳に出ている取引を、現金のまま残している
- 口座振替（自動引落）を除外し忘れている

目標値を入れておくと、計算値との差も表示します。

### 4. 現金出納帳

確定した現金取引だけを日付順に並べ、期首残高から残高を積み上げます。
CSV で書き出すか、そのまま印刷できます。未確定の行を含めた下書き表示にも切り替えられます。

翌月を「月を追加」で作ると、**前月の月末残高が期首残高として引き継がれます。**

## 判定できる／できないこと

できること
- .xlsx の文字色をそのまま読む（CSV では失われる情報）
- 通帳との金額・日付・摘要による突き合わせ
- 過去の判断をルールとして再利用する
- 検算式による整合チェック

できないこと
- **どちらとも取れる取引の最終判断。** 色と通帳で決まらないものは必ず人に回ります
- 経費科目の判断。科目欄は入力・分割できますが、内容の妥当性までは見ていません
- 税務上の取り扱いの判断

金額に関わる部分なので、**初めて使う月は必ず目視でも突き合わせてください。**
2か月目以降、ルールが溜まってから効果が出てきます。

---

## 保存とバックアップ

データはこの端末のブラウザ内（localStorage）にのみ保存されます。外部には送信しません。
ブラウザのデータを消すと失われるため、**月次でバックアップ（JSON）を書き出してください。**
「データ」タブから書き出し・読み込みができます。

## 仕組み

| ファイル | 役割 |
|---|---|
| `xlsx.js` | .xlsx を直接読む最小限のリーダー（ZIP展開＋XML解析＋文字色の解決）。外部ライブラリなし |
| `cashbook.js` | 判定・分割・検算・出納帳の組み立て。DOM に触れません |
| `app.js` | 画面制御と localStorage |
| `cashbook.css` | この画面の追加分。基本は `../styles.css` |
| `sample/資金表-サンプル.xlsx` | 動作確認用のダミー。色つき。ATM行がわざと金額0で入っています |

```bash
npm run test:back-office     # 判定・検算ロジックのテスト
```

締日や検算式、判定の優先順位を変えるときは、**先に `test/cashbook.test.js` に期待値を書いてから**
`cashbook.js` を直してください。5月分の実績（現金純増減 +7,012円／月末残高 156,756円）が
テストの基準値として入っています。

.xlsx の読み取りは DOM を使うためブラウザでしか動きません。
`sample/資金表-サンプル.xlsx` を読み込んで、色が「青／赤／黒」と表示されることで確認できます。
