# バックオフィス — 資金繰り・債権債務管理

事務作業の時間短縮を目的とした社内用ツールです。Excel と手作業で回している
「請求の管理 → 入金の消込 → 資金繰りの把握 → 督促」を 1 画面にまとめ、
いちばん時間のかかる**入出金の消込を銀行 CSV から自動化**します。

- インストール不要・ログイン不要。ブラウザだけで動きます。
- データは**この端末のブラウザ内（localStorage）にのみ**保存されます。外部には一切送信しません。
- 公開サイト（www.meihodo.com / GitHub Pages）には**含まれません**。
  Vercel は `.vercelignore`、GitHub Pages は `deploy.yml` の除外ステップで配信対象から外しています。

---

## 併せて使うツール

- [資金表 → 現金出納帳](cashbook/README.md) — 現金と預金が合算された資金表から、現金だけを抜き出して出納帳を作る（`npm run cashbook`）

## 起動する

```bash
npm run back-office      # http://localhost:3100/back-office/index.html が開きます
```

`index.html` をダブルクリックしても開けますが、ブラウザによっては
`file://` でのデータ保存が制限されるため、上のコマンドでの起動を推奨します。

同じ端末・同じブラウザで開くかぎりデータは残ります。**別の PC とはデータは共有されません。**
複数人で使う場合は、後述のバックアップ JSON を受け渡してください。

## 最初にやること（15分）

1. **設定・データ**タブ →「基本設定」
   - 現預金残高と基準日（通帳の残高をそのまま入れる）
   - 警戒水準（この額を割ったら警告が出る。例：人件費 1 か月分）
   - 振込手数料の許容差：入金時に手数料を差し引かれる取引先があるなら `880` などを入れる
2. **設定・データ**タブ →「取引先マスタ」
   - 主要な取引先の**締日・支払サイト**を登録する → 取引の登録時に期日が自動で入ります
   - **カナを必ず入れる**：銀行の摘要は半角カナなので、カナが無いと自動消込の精度が落ちます
3. **資金繰り**タブ →「固定費・定期入出金」
   - 給与・家賃・借入返済・リース・水道光熱・OTA からの入金など、毎月決まったものを登録
4. 動作を試すだけなら、設定タブの「サンプルデータを入れて試す」→ 確認後「全データを消去」

## 毎日・毎週の流れ

### ① 請求を出したら / 請求書が届いたら（1件30秒）

**債権・債務**タブの登録フォームに入力します。
取引先を選んで発生日を入れると、締日・支払サイトから**期日が自動計算**されます。
期日を手で直した場合は、以後その入力では自動計算で上書きされません。

### ② 通帳が動いたら：銀行CSVの消込（週1回・5〜10分）

ここが最大の時短ポイントです。

1. ネットバンキングから入出金明細を CSV でダウンロード
2. **銀行CSV消込**タブ → ファイルを選択（または CSV を貼り付け）→「読み込む」
   - 文字コード（Shift_JIS / UTF-8）は自動判定します
   - 列（日付・摘要・入金・出金・残高）も自動判定します。違っていればその場で選び直せます
   - **前回取り込み済みの明細は自動的に除外**されるので、期間が重なっても二重計上しません
3. 「自動確定の候補」を確認 → 外したいものはチェックを外す
4. 「要確認」は候補から選ぶ（該当が無ければ「新規登録する」でその場で起票）
5. 「チェックした明細を消込む」→ 対象の債権債務が決済済になり、現預金残高も明細の残高で更新されます

**自動確定の条件**：入出金の向きが合っていて、金額が一致し、期日が近く、
かつ**他に紛らわしい候補が無い**もののみ。1 円でも合わない・候補が 2 件並ぶ、といった場合は
必ず「要確認」に落ちるので、機械が勝手に間違った消込をすることはありません。
慎重にしたい場合は設定の「自動消込のしきい値」を上げてください（既定 65 / 最大 100）。

### ③ 資金繰りの確認（週1回・3分）

**資金繰り**タブ。未決済の債権債務を期日で、固定費を発生日で積み上げ、
13 週先（または 6 か月先）までの残高推移を出します。

**確定と見込みは分けて予測します。**
債権・債務を登録するときに「確度」を選べます。

| 確度 | 用途 |
|---|---|
| 確定 | 請求書・発注書などで金額と期日が固まっている分 |
| 見込み | まだ見積り・計画段階で、金額や時期が変わりうる分 |

資金繰り表には**期末残高（確定ベース）**と**期末残高（見込み込み）**の両方の列が出ます。
警告や資金不足の判定は、常に**確定ベース**（見込みを含まない、より厳しい数字）を基準にします。
見込み案件だけで資金不足が隠れてしまうことを防ぐためです。見込みを含めた数字は、
事業計画を立てる際の参考値として横に表示されます。

- 赤い行 = 確定ベースの残高がマイナス（資金ショート見込み）
- 黄色い行 = 確定ベースの残高が警戒水準を下回る
- 「内訳」を開くと、その期間の入出金の明細が出ます（見込み分には「（見込み）」と付きます）
- 「印刷」で金融機関に出せる形の資金繰り表になります

**本部への資金不足報告**は同じタブの下にあります。確定ベースで警戒水準を下回る時期が
あれば、依頼する資金移動額の目安つきで文面を自動生成します。「文面をコピー」→ 報告に貼り付け。
見込み案件は根拠に含めないので、まだ確定していない売上を当てにした依頼にはなりません。

**見込み案件は月によって内容が変わるものです。** ゼロから毎月入力する代わりに、
**債権・債務**タブの「前月の見込みをコピー」で、前月に発生日がある見込み案件を
日付を1か月ずらして複製できます。複製後に金額・取引先・日付を調整してください。

### ④ 督促（月1回・5分）

**督促**タブ。期日を過ぎた売掛を取引先ごとにまとめ、請求明細入りの文面を用意します。
内容を確認・修正 →「文面をコピー」→ メールに貼り付け。

## バックアップ（必ず月1回）

データはブラウザ内にしかありません。以下の場合に**消えます**。

- ブラウザの閲覧データ（Cookie とサイトデータ）を消去した
- 別の PC / 別のブラウザで開いた（そちらには何も無い状態で始まります）
- PC を入れ替えた

**設定・データ**タブ →「バックアップを書き出す（JSON）」で、
共有フォルダや Google ドライブなどに保存してください。
復元は同じ画面の「バックアップを読み込む」から。

会計ソフトに渡したいときは「全データをCSVで書き出す」を使います。
Excel で開ける形式（UTF-8 BOM 付き）です。逆に Excel の一覧を取り込むときは
「CSVから取り込む」。列は次の順で用意してください。

```
区分,確度,取引先,取引先カナ,請求番号,発生日,期日,金額,状態,決済日,摘要
売掛,確定,株式会社阿蘇観光,アソカンコウ,INV-2601,2026-04-01,2026-05-31,682000,未決済,,4月分
```

区分は「売掛 / 買掛」、確度は「確定 / 見込み」（省略すると確定扱い）、状態は「未決済 / 決済済」。
読めなかった行は行番号付きで知らせます。

## 自動消込の精度を上げるコツ

| 症状 | 対処 |
|---|---|
| 「要確認」ばかりになる | 取引先マスタに**カナ**を登録する（漢字だけでは銀行摘要と照合できません） |
| 手数料が引かれて金額が合わない | 設定の「振込手数料の許容差」に 880 など上限額を入れる |
| 同じ金額の請求が並んで判別できない | 請求番号を登録し、振込依頼時に摘要へ入れてもらう |
| 複数請求をまとめて入金される | 合算額で 1 件登録するか、消込後に金額を分けて登録し直す |
| 逆に消し過ぎが不安 | 設定の「自動消込のしきい値」を 80〜90 に上げる |

## 想定できる時短効果

| 作業 | これまで（Excel＋通帳照合） | このツール |
|---|---|---|
| 入金・支払の消込 | 明細1件あたり 1〜2分の目視照合 | 大半は自動確定、確認のみ |
| 期日の管理 | 手計算・転記 | 締日と支払サイトから自動 |
| 資金繰り表の作成 | 月末に手作業で集計 | 常に最新（作成作業ゼロ） |
| 督促状の作成 | 対象の抽出と文面作成 | 抽出済み＋文面生成 |

実際の削減幅は明細件数と取引先マスタの整備度合いで変わります。
消込画面に「手作業の削減見込 ◯%」として、その回の自動確定率が表示されます。

## 仕組み・保守

| ファイル | 役割 |
|---|---|
| `index.html` | 画面の骨組み |
| `core.js` | 計算ロジック（日付・CSV・照合・資金繰り）。DOM に触れません |
| `app.js` | 画面制御と localStorage |
| `styles.css` | このツール専用。公開サイトの `/styles.css` とは無関係 |
| `test/core.test.js` | `core.js` の自動テスト |

```bash
npm run test:back-office     # 計算ロジックのテスト
```

締日計算・銀行 CSV の解釈・自動消込の判定を変更するときは、
**先に `test/core.test.js` に期待値を書いてから** `core.js` を直してください。
お金の計算なので、目視確認だけで通さない運用にしています。

外部ライブラリ・ビルド手順・通信は一切ありません。公開サイト側のファイルにも触れていません。
